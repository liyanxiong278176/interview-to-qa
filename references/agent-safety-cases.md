# Agent 安全与工具调用：会话参考

仅在主题相关时使用。以下是训练情境与评估要点，不代表用户真实项目配置；不复用原会话的 88 分作为新会话评分。

## 讲解的概念链与校正要点

- 分层防御覆盖输入、第三方数据、工具执行和输出。规则与模型检测是辅助防线，不能替代执行层授权。
- 输入检测结合意图、授权、数据范围和操作后果。包含敏感数据不等于危险请求。内容风险分级与执行权限分别判断。
- 第三方结果是不可信业务数据，不因其中的指令而授予权限。不放进系统提示词仍不能保证模型不受影响。
- DLP 覆盖最终回复、工具参数、外发请求和日志。违规外发应阻断；只有策略允许且脱敏充分时才能继续。
- allow/ask/deny 结合用户、工具、资源、参数、目的地和后果。只读可能泄露；可回滚可能已经触发外部影响；用户确认不覆盖 deny。
- Function calling：定义工具 → 模型提出调用 → 后端验证结构、业务、权限与风险 → 执行 → 返回结果。Schema 合法不代表业务安全；共用注册与校验机制可减少重复适配代码。
- MCP 的 Host 是 AI 应用，Client 是通信组件，Server 提供能力。MCP 标准化发现与调用等交互，服务端仍需业务适配；也有 resources 和 prompts。MCP 不规定模型必须使用某厂商的 function calling API。
- 渐进发现按场景或能力选择，再加载需要的工具定义，是上下文管理策略，不是 MCP 强制流程。发现不等于授权。
- Server 审核与隔离测试之后仍需最小权限、变更检查和运行时控制。未经审核的工具不能只靠每次确认补足安全性。

## 情境 1：只读搜索外泄

内部文档诱导 Agent 把读取到的 API Key 作为外部搜索关键词。调用符合 Schema、工具已在白名单且属于只读。

可追问：在哪里拦截，检查什么，已有输入检测、allow 与最终回复 DLP 为何可能不足？

评估要点：

- 识别间接提示注入；第三方内容检测可能命中，也可能漏判。
- 工具执行前独立检查敏感标签、参数内容、目的地及接收方权限，违反外发策略直接阻断。
- 只读不代表没有信息外发；最终回复 DLP 不能补救已发出的工具参数。
- 标签按策略随编码、拆分、摘要和拼接等派生数据传播；内部接收方也需鉴权。

## 情境 2：白名单工具变更

已经审核的 MCP Server 更新工具描述，诱导读取本地配置并附带到参数；工具名不变，参数符合更新后的 Schema。

可追问：如何发现变更，如何处理，用户确认是否足以放行？

评估要点：

- 保存已审核工具名称、描述、Schema 的基准指纹，发现时比对。
- 变更工具暂停授权、重新审核；无法隔离影响时禁用 Server。校验定义与执行使用的定义绑定。
- 指纹不能发现所有实现变化，还需部署版本或制品校验、隔离及运行时权限控制。
- 用户可能被诱导确认；确认不替代变更审核、敏感数据与流向检查。

## 情境 3：创建工单响应丢失

用户确认创建工单，调用超时，但 Server 可能已经创建成功。Agent 准备重试。

可追问：支持或不支持幂等键时怎样避免重复创建，是否再次确认？

评估要点：

- 同一次业务操作保存稳定幂等键，重试沿用，核实服务端幂等有效期及保证范围。
- 无幂等键但有查询时，用业务唯一标识核对。查不到可能是可见性延迟或请求仍在执行，不能直接判定失败。
- 只有确认未执行且原请求不会随后生效才重试；不能确认时停止自动重试并对账。
- 同一已授权操作、范围和参数不变、幂等保证有效时通常无需再次确认；新增副作用或超出授权时需确认。再次确认不能解决状态不确定。
